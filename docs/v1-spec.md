# Jotport 首版实现规格

状态：规格已确认；应用实现与 macOS 12 实机验收尚未开始。

为 macOS 12 Intel Mac 实现一款轻量的块式草稿纸。用户随意记录灵感和事项；块可以关联本机 Codex CLI 或 pi 会话，使用外部终端交互，并在会话需要用户时提示和上移。本规格供本地开发 agent 实现首版，范围以本节和验收条件为准。

## 已确认的范围

| 项目 | 首版要求 |
| --- | --- |
| 平台 | 仅 macOS，最低 macOS 12，必须提供 Intel x86_64 可运行构建 |
| 技术 | Swift 原生；AppKit 负责窗口和文本编辑；SQLite 本地存储 |
| 终端 | laojianzi/ghostty-monterey 1.4.0 社区版、WezTerm，同为首版验收目标 |
| Agent | Codex CLI、pi，同为首版验收目标 |
| 交互 | app 管理笔记、关联和关注状态；对话继续在外部终端进行 |
| herdr | 遇到可复现的直接接入缺口时评估复用，默认直接适配 |
| 后续扩展 | 数据结构允许网页及其他关联；首版不实现完整插件系统 |
| 暂缓 | iTerm2、其他 agent、跨平台和云同步 |

用户已确认 Ghostty 的仓库和 App 版本 1.4.0。首次接入由程序读取实际安装路径、bundle identity、构建号和脚本字典；不把 1.4.0 自动等同于某个 monterey 修订版，也不再要求用户为构建号反复确认。社区版依据：[Ghostty Monterey 仓库](https://github.com/laojianzi/ghostty-monterey)。

## 首版使用流程

用户创建一个块，写下“排查项目按钮无响应”，下一段补充“先检查事件绑定，再检查遮罩层”。用户点击主按钮并选择项目文件夹。Jotport 保存块的启动路径，使用预设的终端和 agent 在该目录启动会话，并预填块正文。用户按回车后发送正文。正文仍可编辑，再次点击主按钮会返回同一会话。agent 需要授权、回答或结果查看时，块显示对应状态，并按排序规则上移。

设置保存默认终端、默认 agent、可执行文件和参数。启动路径由用户为每个块选择。块没有可用的启动路径时，启动前打开文件夹选择器。路径失效时，先提示用户原路径已不可用。取消选择就结束本次启动。

未绑定会话的块可以在块菜单里修改启动路径，也可以通过「选择 agent 和终端…」为本次启动选用其他配置。绑定会话后，启动路径锁定。用户可以从块菜单清理绑定。清理会将当前会话关联存入历史，保留块的启动路径，并重新开放路径修改。用户可以在任意会话状态下清理绑定。正在运行的 agent 会继续在终端运行。

## 文本块和搜索

- 单块支持单行、多行、多段和空白行。Enter 留在块内换行；使用独立的新建入口创建下一块。

- 主窗口用单列显示所有可见块，正文直接在块内编辑。鼠标悬停在块上时，左侧显示拖动手柄，右侧显示「…」。鼠标移入「…」时，块快捷操作以胶囊按钮向左展开。点击「…」可打开完整菜单。拖动从手柄发起，行尾操作在拖动期间收起。

- 默认的块快捷操作依次是「启动 / 返回」「复制」「置顶」。设置允许从内置操作中添加、移除和排序。

- 所有正文按普通文本处理，不要求待办符号、标题或类型选择。原生编辑器保留中文输入法、选择、复制和撤销行为。

- 自动保存正文及顺序；应用正常退出前完成待保存事务。意外退出后保留最后已提交的数据。

- 每块支持整块复制、归档、恢复、删除撤销、置顶和拖动。点击「复制」会复制正文，成功后短暂显示「已复制」。会话 ID 和概况通过独立操作复制。

- 默认搜索未归档且未删除的块；“包含已归档”开关扩大范围。搜索正文、只读概况、agent 名称、工作目录和所有历史关联会话 ID。

- 删除的块进入可撤销记录，不出现在普通搜索；删除撤销恢复原关联。归档不改变会话身份。

- 中文关键词、多段文本、大小写和会话 ID 搜索必须验收。首版不依赖索引完整终端输出或所有历史对话。

## 窗口和关注排序

每次启动时，「窗口置顶」复选框均未勾选。勾选后开启置顶，切换到终端时笔记窗口可继续可见。取消勾选后恢复普通窗口层级。收到状态事件时不抢占键盘焦点。普通桌面、多桌面和全屏场景分别验证。实现依据见 [AppKit 窗口层级](https://developer.apple.com/documentation/appkit/nswindow/level-swift.property)和[窗口空间行为](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct)。

以下为首版交互默认值：

1. 手动置顶的块排在最上方，置顶区保持用户排列。

2. 非置顶块出现新的关注事件时，移到置顶区之后的第一位。按事件发生顺序依次提升，最新事件在上；延迟和乱序事件先按会话轮次校验。

3. 同一关注事件只提升一次。持续等待、重复上报和定时对账均不能重复抢位置。

4. 用户拖动后保留该顺序，直到该块出现下一次新的关注事件；agent 恢复运行时不自动把块降回旧位置。

5. 置顶区内的关注事件只更新标记，不打乱置顶顺序。跨置顶区的拖动不暗中改变置顶属性。

6. 正在输入、输入法组词、拖动或搜索时暂停视觉重排；操作结束后只应用仍然有效的关注事件。

7. 成功跳回对应会话可把当次提醒标为已查看，但不把实际的等待输入状态改成运行中。

8. 首次启动后的待发送状态不计为任务完成，不产生完成提醒。

## 身份和数据模型

块、对话、运行实例和终端位置必须分别保存。正文编辑不能改变绑定；窗口标题、工作目录或 PID 不能单独代表一个 agent 会话。

| 记录 | 最少信息 |
| --- | --- |
| Block | 稳定 UUID、正文、正文修订、启动路径、手动顺序、置顶状态、归档与删除时间、创建与更新时间 |
| Association | 稳定 UUID、块 ID、关联类型、agent 类型、原生会话 ID、工作目录、当前或历史标记 |
| Run | 唯一运行 ID、关联 ID、启动请求 ID、正文快照、状态、当前轮次、最近有效事件、进程身份 |
| TerminalRef | 实际 app 路径与 identity、终端运行代次、terminal 或 pane ID、必要的窗口与标签引用 |
| AttentionEvent | 唯一事件 ID、运行与轮次、原因、发生时间、是否已查看、是否已提升 |
| Recap | 来源会话与轮次、内容、内容类型、更新时间、是否过期 |

每块只绑定一个当前 agent 会话。历史会话关联保留原生会话 ID，可用于搜索块。网页扩展可使用新的 Association 类型。当前 Run 和 TerminalRef 可以变化。

## 启动和重复点击

| 情况 | 主按钮行为 |
| --- | --- |
| 未绑定会话，启动路径可用 | 在该路径建立启动请求，保存正文快照，启动默认或所选 agent |
| 未绑定会话，启动路径未设或已失效 | 打开文件夹选择器，保存所选路径后发起启动 |
| 正在启动或等待结果 | 复用同一次请求，显示进度；不再新建 |
| 会话仍在当前终端 | 核对身份后聚焦该会话，不重复粘贴正文 |
| 当前绑定的会话已退出且可恢复 | 按保存的原生会话 ID 恢复，不重发原始或修改后的正文 |
| 状态未知或定位失败 | 先重新核对，显示具体失败原因和恢复入口，不静默另开新对话 |

启动锁在第一次点击时建立，并持续到有明确成功或失败结果。启动超时不等于未创建；重试前检查已有运行实例。app 重启后的未决请求也要对账，不能直接重放。每次重启运行生成新的 Run ID，拒绝旧实例的迟到退出事件覆盖新状态。

正文按点击启动时的快照预填。用户在启动过程中继续修改正文，不暗中替换待预填内容。首次注入记录为已完成，恢复窗口或再次点击不重复注入。

## 终端适配

两种终端实现相同的能力接口：检测安装与权限、启动、定位、输入文本、聚焦、查询存在性和关闭指定目标。必须控制用户实际选中的安装包，避免官方版和社区版共存时控制错实例。

### Ghostty 社区版

直接适配优先使用安装包实际暴露的 AppleScript 接口。参考映射如下，安装包脚本字典是最终依据：

| 能力 | 接口方向 |
| --- | --- |
| 目录与启动配置 | new surface configuration，设置 initial working directory、command、environment variables |
| 创建 | new window 或 new tab，随后取得对应 terminal |
| 定位 | 保存 terminal id，并同时记录终端运行代次 |
| 返回 | focus 指定 terminal |
| 预填 | input text，仅输入正文 |
| 发送 | 用户在 agent 中按 Enter；app 不追加发送按键 |
| 关闭 | close 已核验的 terminal |

new window 返回的是 window，不能直接当作 terminal 使用。不要把 surface configuration 的 initial input 当作输入框就绪保证。通过参数或 Apple event 字符串描述符传递正文，不把正文拼进 AppleScript 或 shell 源码。Automation 权限或 macos-applescript 配置不可用时显示明确的接入错误。接口依据：[Ghostty AppleScript](https://ghostty.org/docs/features/applescript)。

### WezTerm

使用官方 CLI 创建、查询和控制指定 pane，保存 spawn 返回的 pane ID。支持目录和参数传递，并在跳转时完成 pane 选择及所属应用前置。pane ID 不视为跨终端重启永久唯一。参考：[spawn](https://wezterm.org/cli/cli/spawn.html)、[send-text](https://wezterm.org/cli/cli/send-text.html)、[activate-pane](https://wezterm.org/cli/cli/activate-pane.html)、[list](https://wezterm.org/cli/cli/list.html)。

## Agent 适配和预填

按本机可运行的 CLI 版本探测能力，记录实际版本及可用事件。安装或合并本 app 的 hooks、扩展时保留现有配置，包括已有项目工作流；接入可撤销，并通过启动关联标记限定上报范围。

pi 优先通过扩展读取原生会话 ID、监听运行和交互事件，并使用 setEditorText 或 pasteToEditor 预填输入框。具备 agent_settled 的版本使用它判断本轮不会再自动继续；较旧版本只能依据实际接口建立可验证的替代方案。依据：[pi 扩展文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md)。

Codex 优先通过其 hooks 或正式事件接口取得会话 ID和状态，恢复必须指定已保存的会话 ID。SessionStart、进程存在、终端无输出或 idle 状态本身，都不能证明输入框可以接收正文。需要实际验证启动、登录、信任提示和恢复菜单等情况下的输入就绪判断。依据：[Codex hooks](https://learn.chatgpt.com/docs/hooks)、[CLI 命令](https://learn.chatgpt.com/docs/developer-commands?surface=cli)。

预填只在目标身份和输入区域均已确认时执行。多行正文保留原文，不自动提交。无法确认时可显示“已打开，待粘贴”并提供复制入口；这是明确降级，该组合的自动预填验收仍未通过。不能把命令行初始 prompt 参数、自动发送工具或固定等待几秒视为预填方案。

## 状态和事件桥接

块只有在确认关联的终端会话 ID 后，才在左侧显示会话状态图标。鼠标悬停图标时可查看状态文字，使用「启动 / 返回」打开终端。

| 显示状态 | 证据与行为 |
| --- | --- |
| 启动中 | 已创建启动请求，尚未完成会话与输入状态确认 |
| 待发送 | 输入区域已确认并完成预填，用户尚未提交 |
| 运行中 | 有当前轮次的实际运行事件 |
| 需要输入 | 有当前会话的权限、问题或交互等待证据 |
| 结果待查看 | 本轮可靠结束并产生尚未查看的结果 |
| 已退出 | 已确认对应运行实例结束。仍有原会话记录时可以恢复 |
| 状态未知 | 连接、事件或身份信息不足，等待重新核对 |
| 错误 | 有明确启动、运行或恢复失败，保留可理解的原因 |

关注提醒与运行状态分别记录。例如成功打开终端后，提醒可变为已查看，而 agent 仍保持需要输入。只有主会话的相关事件影响该块，子 agent 停止不能误报主会话已经完成。

Stop hook 可能继续触发工作，不能把任何一次 Stop 直接当作最终闲置。支持的适配器应优先使用最终状态事件；否则结合后续事件进行校准。等待用户的具体类型不能仅从通用 Notification 名称推断。若无法可靠区分，显示状态未知或较保守状态。

本地事件桥接应保持小型、事件驱动。建议 hooks 或 pi 扩展将结构化事件交给一个轻量 Swift helper；helper 将事件可靠写入本地收件目录，app 监听并消费。app 不在运行时事件可留存，重新打开后按当前运行状态校准。事件包含 schemaVersion、eventID、runID、sessionID、turnID（可用时）、来源、类型及时间；重复、乱序和旧运行事件不得反复改变状态。

桥接只记录观察结果，不通过 hook 返回继续执行、批准或拒绝等决策。原 agent 的执行和退出不能因为 app 未开启或短暂写入失败而被长时间阻塞。会话恢复、app 唤醒、连接中断和异常退出时进行必要对账；普通空闲笔记状态下不持续扫描终端。

## 会话概况

有最近回复摘录的块默认在正文下方显示浅色只读摘录，同时保留来源会话、轮次和更新时间。鼠标悬停摘录时，右侧显示「隐藏」。隐藏后可通过块的「…」菜单中的「查看最近回复」重新打开。只有实际经过总结的内容才标为「自动概况」。

优先利用结构化事件提供的最近回复；必要时在适配器内按选定版本读取会话记录。摘要生成在后台进行，不阻塞原会话，也不强迫 agent 额外执行一轮。有可用摘录时才显示摘录区域。上一次结果可保留，需标明更新时间或过期。真正的模型概况可在后续增加，首版不依赖常驻总结任务。

## 关闭 归档 删除和恢复

- 归档负责收起块，不终止 agent，也不删除关联。归档中的会话需要关注时提供轻量入口，不自动取消归档。

- 删除负责移除笔记，可撤销；不默认终止 agent。保留撤销所需关联，迟到事件不能重新创建已删除块。

- 结束 agent 是独立操作，只作用于已核验的运行实例。优先正常退出，必要的强制终止明确单列；不关闭整个终端应用。

- 关闭 app 不默认终止外部会话。再次启动先核对原会话状态和终端位置，再显示或恢复。

- 关闭终端窗口只证明显示连接发生变化；应结合实际运行状态判断任务是否仍在后台继续。

- 会话已退出时按原生 ID 恢复。找不到原会话记录时，向用户说明恢复失败的原因。

- 用户在终端中执行新建、清空或切换会话后，核验新的原生 ID。原窗口已经承载另一对话时，不向它再次注入正文；返回原对话应使用原 ID 恢复。

## herdr 的引入条件

默认实现直接终端适配与 agent 适配。只有遇到可复现的运行定位、重新连接或输入控制缺口，且直接方案无法可靠满足验收时，才在同一会话运行接口下评估 herdr。

Herdr TUI 的 agent 启动、输入和恢复机制可参考或复用；herdr-core 是可供自建 app 使用的无界面运行时。二者的接口与能力分别核实，不能互相套用。herdr 的 terminal address 不替代 Codex 或 pi 原生会话 ID，闲置状态也不自动等于输入框就绪。

引入前验证：选定版本在 macOS 12 Intel 可运行；可以只预填而不发送；能与外部终端正确连接和返回；额外资源开销符合轻量目标；关闭显示窗口后会话保活的语义清楚。后台仍运行时显示后台状态，用户使用结束 agent 操作才停止任务。参考：[Herdr TUI 自动化](https://herdr.dev/tui/docs/agent-automation/)、[herdr-core](https://github.com/herdrdev/herdr-core)。

## 实现顺序与验收

第一阶段先实现最小纵向原型：一个文本块、两种终端与两种 agent 的启动和定位。优先解决多段预填不发送、真实 ID 绑定、重复点击返回和关闭后的状态，再扩展完整笔记界面。

第二阶段完成原生块编辑、自动保存、整块操作、搜索、置顶与拖动。第三阶段完成事件桥接、关注排序、只读概况和重启恢复。第四阶段在目标 Mac 上完成下表四种组合及公共行为验收。开发过程记录确实遇到的接口缺口，再决定是否引入 herdr。

| 终端 | Agent | 启动和预填 | ID 绑定和重复返回 | 状态和关注排序 | 关闭与恢复 |
| --- | --- | --- | --- | --- | --- |
| Ghostty 社区版 1.4.0 | Codex CLI | 待本机验证 | 待本机验证 | 待本机验证 | 待本机验证 |
| Ghostty 社区版 1.4.0 | pi | 待本机验证 | 待本机验证 | 待本机验证 | 待本机验证 |
| WezTerm | Codex CLI | 待本机验证 | 待本机验证 | 待本机验证 | 待本机验证 |
| WezTerm | pi | 待本机验证 | 待本机验证 | 待本机验证 | 待本机验证 |

公共验收至少覆盖：
