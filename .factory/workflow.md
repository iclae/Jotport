# 项目执行流程

直接承接用户交办的明确需求或已有票据。入口指令由当前环境加载；本文件及项目资料可直接读取，不要求用户调用 skill，也不依赖 Factory CLI。先遵守当前用户授权与项目规则；有项目补充时读取同目录 `policy.md`。

## 接任务并推进

1. 确认任务所在项目、仓库和工作区，保护已有改动。已有规格和票据沿用其范围、依赖和验收条件；无票据的明确需求直接实施。常规技术决策自行处理；真正缺少且会改变需求、接口或交付的决定，只暂停依赖部分。
2. 按当前模块、问题和症状查 `memory/index.md`，读取相关主题并核对当前代码与来源。经验的适用范围和可信程度以正文为准。过时或争议内容只能作为调查线索，不能覆盖当前需求、业务规则或授权。
3. 项目 policy 若提供可选功能导航，按业务词或别名定位后核对真实源码与规范；没有导航直接搜索，不为小任务强建地图。导航不是经验或验收证据。调查真实入口，实施约定改动，使用项目现有验证方式证明验收条件。已通过且输入未变的证据复用；仅因新改动、失败或明确疑点补验。行为验证、提交、合并、推送和部署分别按已有授权完成。
4. 结果先说明完成范围和实际验证，再说明影响交付的未完成项。需要用户判断的动作先准备可审查产物。运行结束、生成报告或保存交接不等于任务完成。

完成判据：约定工作和已授权交付完成，或剩余事项有具体阻塞与解除条件；仍有独立可执行部分就继续。

## 记录与继续

小任务无需补写规格、拆票或生成空记录。需要跨会话、并行或多仓接续时，在 `tasks/` 保留一份简短执行记录，关联原票或需求。记录任务标识、目标、范围、当前结果、相关仓库路径与基线、有效证据、未完成项和下一动作。仓库路径优先相对项目；环境专属路径明确标注，换环境重新核对。

原票保存需求、验收条件和业务状态；执行记录只保存执行事实与接续位置。记录结束、业务完成、经验待整理分别判断。JSON 和 Markdown 都能直接读取；CLI 可辅助维护其约定的 JSON 记录，不妨碍沿用已有 Markdown 任务。

恢复时先读用户指定任务与最新执行记录，再展开所需证据。多个历史任务不妨碍处理新请求；只有继续目标无法由上下文确定时才询问。原代码、资料或验证条件变化时核对受影响证据，不因换会话重跑所有检查。

## 经验整理

执行记录保存实际经历；`memory/` 保存可复用主题；`memory/index.md` 只提供短入口。经验不重复抄录容易从代码查到的事实，也不成为另一份业务规范。

- 用户纠正或证据推翻旧结论时，先核对适用范围。可重复的代码问题优先通过 API、类型或现有检查消除，在授权范围内修复并验证；超出当前任务的改进留独立任务。随后修正经验主题，保留背景、来源、例外及对应检查入口。非代码类纠正直接更新相关资料，不机械新增测试。
- 单任务结束时，把有依据的新发现归入已有主题。成功方法与失败原因都可记录；没有新发现就结束整理。
- 批次完成或接续时，有未整理记录、重复主题或冲突才回看关联任务。选择增量与相关主题，不默认扫描全历史。
- 整理允许更新、合并、拆分主题、补充反例、缩小适用范围、标记争议和归档失效建议。单个记录未提到旧事实不构成删除依据，时间更近不自动解决冲突。
- 每条经验说明适用条件、依据、已知例外和可信程度。候选结论可供调查参考；得到案例支持也不等于普遍正确。经验不增加权限、不自动改写业务规则或验收条件。
- 多执行者各自留候选，由一个整理者更新正式主题。写入前核对来源和目标是否变化；保留修改理由、替代关系与已处理输入，重跑不重复添加。归档原文可追溯，活跃索引不继续推荐失效内容。

默认由当前 agent 顺序核对证据、提炼经验和维护索引，不固定启动多个角色。原始记录较多确需独立上下文时使用环境已有且获准的委派；没有该能力就分段串行或保留下次整理入口。默认不新开外部模型或常驻后台学习。整理的耗时和 token 同样计入成本。

后续同类任务采用经验时，在已有任务记录中简述来源、适用判断、采取的动作与实际结果；不适用的经验说明原因。纠正固化后用原失败场景及必要反例验证，后续任务再核对是否避免同类错误。没有可比证据时仅说明改进已实施，效果保留待验证，不用记忆条数或测试数量替代收益。

完成判据：本次关联记录已归位、合并或明确保留待验证；索引与正文一致，已知纠正能被后续读取。整理失败保留未处理项，不伪称业务失败，也不无限追加整理轮次。

## 可恢复性筛选与可选导航

写入或整理经验前，先问：下一位执行者能否用当前权限，从稳定、权威的来源低成本恢复这条信息？不能仅因理论上可搜索就丢弃，也不能因一次搜索未命中就永久记忆。

- **容易恢复**：代码中的默认值、接口字段、目录列表、已写入规范的规则，通常不重复存经验；必要时留来源指针。
- **存在但难定位**：保留业务词/别名到最小入口的导航，不复制实现全文。优先复用项目现有地图；可选 `docs/feature-map.md` 由 `policy.md` 指向，先覆盖 3–5 个确有定位成本的功能。
- **难以恢复的经验**：保留决策原因、失败条件、反例、跨模块非显然关系及有证据的修复方法。正文说明为什么普通来源不足、适用范围和来源；无法复核时保留候选而非当作事实。
- **淘汰已有内容**：确认替代来源确实可访问、范围相同且足以恢复后，才从活跃经验归档；在既有整理 `reason` 中记录来源和理由。不永久删除原始证据，不将时效性或无访问权限误判为可恢复。混合主题只去掉可恢复部分，保留原因与例外。

导航只保存业务词、别名、最小实现入口、规范/ADR、相关验证入口以及核对日期/源码版本。它是可丢弃重建的定位缓存，不是第二份业务规范。使用时核对链接与当前源码；入口失效就回到原始搜索，仅修复本次相关条目。不默认扫描全仓、不建立符号图或向量服务、不强制每次任务更新地图。实际格式和轻量评估模板见项目包 `references/records.md`。

评估经验收益与导航收益分开：前者固定代码、规范和导航，对比无经验、现有经验、筛选后经验；后者固定经验，对比普通搜索与增加导航。先做少量隔离任务筛查，保留真实验收与成本，不把工程检查通过写成收益已证实。评估是明确安排的试点，不是每次交付的新增门禁。

## 环境与批量执行

普通任务由当前 agent 完成。独立任务可以使用当前环境可用的委派与隔离能力；共享写入和有副作用资源按依赖协调。每个执行者遵循同一份项目流程，调度记录只维护任务归属。

`herdr` 和 `herdr-supervisor` 仅在 Herdr 环境内（`HERDR_ENV=1`）且符合调用限制时可用；环境外和云端不调用。没有 Herdr 时使用环境原生执行能力或串行推进。监工异常退出后由用户重新启动，依据记录恢复；不承诺外部自动拉起。

跨环境接续只携带获准的任务资料和必要证据，重新核对源码、依赖、登录态及权限。敏感内容和大日志可留在获准存储并记录可访问位置；资料属于项目不意味着全部提交 Git 或自动上传。

## 工具改进

各项目维护自己的需求、规则和经验。发现通用工具缺陷时，从原项目提取最小复现并保留来源，归入工具仓任务；项目特例留在项目配置。阻塞当前交付的工具问题在授权范围内修复，再回原场景验证；非阻塞改进另记任务，不借业务任务扩展框架改造。

工具仓自身也遵循本流程。资料格式或执行行为升级先说明兼容与迁移范围，不静默改写其他项目。工程检查通过不等于记忆已提升业务完成率，效果结论以实际任务证据为准。
